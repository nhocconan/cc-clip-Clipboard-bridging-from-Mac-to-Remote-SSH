## What's New in v0.13.6

Image paste works again in Claude Code 2.1.330 and later on remote hosts using
the xclip shim. Claude Code began asking for the clipboard with `-o` before
`-t`:

```
xclip -selection clipboard -o -t TARGETS
xclip -selection clipboard -o -t image/png
```

The shim matched arguments by their order in the joined command line, so this
shape went to the text-read branch. Claude Code never saw `image/png` and
showed `no image over SSH`, while `cc-clip doctor` still passed because its
image probe calls the daemon directly rather than through the shim.

The shim now parses arguments one at a time (`-selection`, `-t`/`-target`,
`-o`/`-out`), so the order no longer matters. With `-selection clipboard` and
`-o`, a `TARGETS` target lists types, an `image/*` target reads the image, no
target or a plain-text target reads text, and any other target (for example
`text/html`) passes through to the real xclip as before. Clipboard writes are
unchanged.

Verified against Claude Code 2.1.332: Ctrl+V on the remote attaches the image.
Upstream report: ShunmeiCho/cc-clip#197.

## Upgrade

The fix lives in the shim script on each remote host, so redeploy every host
after updating:

```sh
cc-clip update --to v0.13.6
cc-clip connect <host> --force
cc-clip doctor --host <host>
```

Keep the target flags you originally deployed, such as `--codex` or `--all`.
