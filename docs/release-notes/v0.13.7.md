## What's New in v0.13.7

Antigravity (agy) Stop notifications work again. agy 1.4.3 and later load
plugin hooks only from a `hooks.json` at the plugin root, keyed by hook name:

```json
{
  "cc-clip-notify": {
    "Stop": [{ "type": "command", "command": "cc-clip plugin run agy-notify", "timeout": 10 }]
  }
}
```

Earlier cc-clip releases wrote only `hooks/hooks.json` in the flat
`{"Stop": [...]}` shape. agy never read that file, so the plugin showed up in
`agy plugin list` while no notification was ever sent. cc-clip now writes the
root file, and keeps `hooks/hooks.json` for agy 1.0.x, which reads only that
path. Each agy version loads exactly one of the two files, so a Stop event is
never delivered twice. The plugin manifest version moves to 0.2.0.

Verified with agy 1.5.16 on Linux: `agy plugin validate` counts one hook, the
agy log reports `loaded 1 named hooks`, and a finished turn shows up as an
`agy` delivery receipt in `cc-clip doctor --host <host>`.

## Antigravity image paste

Image paste via the cc-clip shim is re-verified with agy 1.5.16. agy still has
no clipboard bridge of its own over SSH: it reads images over SSH only through
X11 or Wayland forwarding (`ssh -X`). Without `DISPLAY` set, agy shows
`Can't read your clipboard over SSH` and never calls `xclip`; the deploy notice
now explains this. Launch it with `DISPLAY=:0 agy` on a headless X11 host, as
before.

## Upgrade

```sh
cc-clip update --to v0.13.7
cc-clip connect <host> --agy
cc-clip doctor --host <host>
```

`--agy` reinstalls the agy plugin and leaves your Claude and Codex
integrations in place. Run your usual `cc-clip connect <host> --force` (with
the target flags you originally deployed) as well if this host has not yet
received v0.13.6's xclip shim fix for Claude Code 2.1.330+.
