## What's New in v0.13.5

SSH clipboard connections now release their own stale reverse forwards after
VPN/Tailscale changes, even when the old TCP connection silently stops moving
packets. The screen wrapper runs a server-side watchdog, preserves the remote
screen and its programs, and reconnects after transport failure.

The experimental `cc-clip tunnel run` supervisor also runs a server-side
watchdog instead of leaving a forwarding-only SSH session behind.

## Other Improvements

- Reconnects can recover a previous tunnel belonging to this workstation using
  a private lease, UID, `sshd`/`sshd-session` name and Linux process start ticks.
- Other users, workstations and unowned legacy listeners are not automatically
  terminated. Legacy conflicts now get a bounded 20-second wait with guidance.
- Local locks recover from dead wrappers; terminal closure and blocked probes
  have bounded cleanup, including SSH children which ignore SIGTERM.
- Loopback HTTP probes bypass proxy environment settings.
- A dedicated regression audit runs in CI for tunnel lifecycle and ownership.
- Windows daemon state writes briefly retry sharing conflicts when a concurrent
  reader prevents file replacement, avoiding lost notification receipts.

## Upgrade

```sh
cc-clip update --to v0.13.5
cc-clip connect <host> --force
cc-clip doctor --host <host>
```

Keep the target flags you originally deployed, such as `--codex` or `--all`.
The screen wrapper is a separate script: a binary update alone does not replace
an existing copy in `~/scripts`. Extract the matching release archive and copy
its script:

```sh
mkdir -p ~/scripts
cp scripts/ssh-cc-clip.sh ~/scripts/ssh-cc-clip.sh.new
chmod +x ~/scripts/ssh-cc-clip.sh.new
mv ~/scripts/ssh-cc-clip.sh.new ~/scripts/ssh-cc-clip.sh
~/scripts/ssh-cc-clip.sh <host>
```

## Requirements and Limits

The screen wrapper requires macOS `shlock` or Linux `flock`, and a Linux remote
with `/proc`, `ps`, `curl`, `screen`, and one numeric IPv4 loopback RemoteForward.
It refuses automatic cleanup when ownership cannot be verified. An already
stale connection created by an older wrapper or plain SSH needs one-time owner
identification; see the [troubleshooting guide](https://github.com/nhocconan/cc-clip-Clipboard-bridging-from-Mac-to-Remote-SSH/blob/v0.13.5/docs/troubleshooting.md).

The public health check in the screen wrapper identifies cc-clip, not a specific
installation. The managed tunnel supervisor also checks authenticated identity.

## Verification

Before extracting a downloaded archive, compare its SHA-256 with the matching
entry in the release's `checksums.txt` (`shasum -a 256 <archive>` on macOS,
`sha256sum <archive>` on Linux).

Validation includes the full Go race suite, lifecycle ownership regressions,
macOS system Bash 3.2, and a live isolated Linux-server test: pausing the SSH
client released both remote listening sockets within 18 seconds, preserved the
screen, and reconnected after resuming the client. This simulates a transport
blackhole; it does not claim to test every VPN product or network failure.
